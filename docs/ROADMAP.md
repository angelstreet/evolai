> Single source of truth for delivery. Mirrors [PRD §18](PRD.md#18-rollout-phases-timelines-and-gates);
> the public copy of the PRD is anonymised ("the pilot client"); this roadmap never refers to a real client.

Each milestone below is delivered as its own branch and pull request against `main`. CI must be green
before merging. After a merge the **State** column and the README's **Status** block are updated in the
next commit on `main` (or in the merging PR).

- **Gate C — enterprise hosting:** done in TASK-K: production hosting (Vercel, Neon), no public credentials,
  auditor CLI, login lockout, security headers, health check, retention cron, runbook. Still open: SSO/OIDC and MFA
  for auditors and company admins (PRD §15); the recovery drill run once with a recorded result; a penetration test;
  an agreed SLA.
- **Gate D — cross-company benchmarks:** not started (Phase 3).
- **Invitations and reminders (FR-03):** done in TASK-N (ADR 0033): bulk links with CSV and QR sheet, optional
  email delivery behind a provider interface, per-team tracking with a minimum group of 5, reminders by cron or a
  resend list, revoke, extend and regenerate, with an admin Invitations page (progress tiles, per-team bars, export, reminders). Still open: a nav link from the restyled admin shell (TASK-L), a live run of the Brevo adapter (needs the owner's key),
  and the owner telling each client about the address window before email mode is switched on.
- **Client referent space (TASK-P, ADR 0035):** done: the owner can view the app as a client referent (read only,
  audited), real referents can sign in to `/client` (progress, invitations for their team, approved results), and
  `pnpm seed:client` seeds the first client. TASK-S (ADR 0039): the referent lists, copies and shares every link
  with a ready-made French or English message, sends one generic reminder on suggested days, and sees per-team
  progress with a minimum of 5 answers before any exact count; no per-link status ever reaches the referent.
  Still open: a separate sponsor account (the published report is the engagement-level, sponsor-level aggregate;
  today it is read in the referent space and sent to the sponsor as a PDF), and SSO for client users. The first
  referent's real login is now self-service (TASK-U, ADR 0040).
- **Audit report (TASK-V, ADRs 0041-0043):** done: catalogue of 29 interventions (simplify, automate, train, AI

  edits or rejects each step; deterministic readiness score per axis and per team (5 or more people, complementary
  suppression); report with executive summary citing approved findings, ranked opportunities (impact and effort),
  steps with owner and timing, risks and prerequisites, 30/60/90-day plan, method and privacy note; draft, in
  review, published, versions, unpublish, audit trail; preview as the client; read-only Report tab and PDF for the
  client; optional AI draft of the summary on the worker. Still open: model re-ranking of steps, measured follow-up
  of the plan (FR-11 pilot tracking), slide export.
- **Real devices and assistive technology:** a run on real phones at 360 px and a human screen-reader pass.
  The axe and keyboard gates cover automation only.

## Gates (PRD §25.4)

- **Gate A — survey pilot:** tenant isolation, retention, audit logs, approved AI data route.
- **Gate B — AI synthesis:** redaction, prompt-injection tests, source traceability, model cost ceiling.
  Status (TASK-H, ADR 0029): all four controls are implemented and proven on the mock provider in
  CI (unit tests, injection suite, DB test, `pnpm ai:eval`). One manual run on a cheap real model
  (`anthropic/claude-haiku-5-5`, synthetic FR/EN gold set) kept 100 % grounded claims and dropped
  2 of 40 proposed items. Still open: an EU-hosted or self-hosted route, a human read of
  real-model theme quality, a contract-approved route before any real survey data, and an admin
  UI for redaction terms. The default route stays `rule-based/v1`.
- **Gate C — enterprise hosting:** recovery drill, SSO/MFA, penetration test, agreed SLA.
- **Gate D — cross-company benchmarks:** aggregation thresholds, de-identification review.

Each milestone explicitly records which gates its tests advance and which it does not.

## Conventions
